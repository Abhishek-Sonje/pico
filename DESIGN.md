# Pico Design System

Pico is a warm, technical opportunity radar. It should feel precise and transparent rather than futuristic or opaque.

## Visual language

- Warm off-white canvas (`#f2f2ed`) with white working surfaces.
- Forest green (`#02261a`) provides structure; electric lime (`#b2e659`) marks action and signal strength.
- Borders establish most hierarchy. Soft, offset shadows are reserved for meaningful elevation.
- Structured grids and isometric pipeline geometry explain how Pico transforms source data. Decoration must remain tied to collection, validation, scoring, or health.

## Typography

- Geist Sans for interface and editorial copy.
- Geist Mono only for measurements, statuses, scores, IDs, and technical values.
- Display tracking never exceeds `-0.04em`; body copy stays within roughly 62–72 characters.

## Interaction

- Controls are at least 44px tall except compact, clearly secondary actions.
- Every interactive element has a visible keyboard focus ring.
- Motion communicates flow or direct manipulation. Reduced-motion mode replaces looping signals with a static lime state while retaining short interaction feedback.
- Drawers use the native dialog model so focus, Escape, and modal semantics remain dependable.

## Voice

Copy is concise, technical, and honest. Pico names its public sources, exposes score reasons, marks demo data, and never describes validation and recovery as an autonomous repair agent.

## Surface modes

- Landing page: Persuade through the product’s real collection-to-decision workflow.
- Dashboard and source health: Operate with scanability, provenance, and recovery ahead of decoration.

## Accessibility and responsive behavior

Maintain WCAG AA contrast, keyboard access, visible focus, semantic landmarks, resilient wrapping, and useful layouts from narrow mobile screens through wide desktop displays. Never encode health or score meaning by color alone.
